# Ghostline Linux L3 (System DNS + Recovery) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect on Linux points the whole system's DNS at Ghostline through NetworkManager, systemd-resolved or `/etc/resolv.conf`, and every recovery path gives it back. Behind this, the orchestrator speaks one OS-neutral DNS interface.

**Architecture:**
- `sysdns.Backend` replaces the adapter-shaped `app.DNS`.
- Windows: `AdapterBackend` wraps today's `Manager`, and absorbs the "new adapter" logic from `app/health.go` and `stillOurs` from `watchdog`.
- Linux: three backends (`networkmanager`, `resolved`, `resolvconf`), picked by `DetectLinux`. They are built on small D-Bus interfaces with godbus implementations, plus `internal/netwatch` (netlink).
- `state.json` moves to v4, keeping the snapshot as `model.DNSSnapshot`.
- Port-53 owners, resume, `secrets` and daemon hardening complete the Linux side.

**Tech Stack:** Go 1.26, `github.com/godbus/dbus/v5` (already in go.sum; becomes direct), `golang.org/x/sys/unix` (netlink, inotify, flock), AES-GCM from the stdlib, React for one Settings change.

**Spec:** `docs/superpowers/specs/2026-10-08-ghostline-linux-l3-design.md` (§ numbers below refer to it). Parents: the L2 and Linux master specs.

## Global Constraints

- **Windows behaviour is unchanged.** Every existing test passes, with only mechanical signature updates. Windows recovery still:
  - restores only adapters still on loopback;
  - resets loopback adapters to DHCP on a corrupt state;
  - logs `ADAPTER_ADDED` for an adapter that appears while connected.
- **No new Go modules.** godbus moves from indirect to direct in `go.mod`. `go mod tidy` must leave `go.sum` unchanged except for that.
- **Shared code** never branches on `runtime.GOOS`. Linux backends live in `internal/sysdns/linux*.go` (`_linux.go` for the godbus/inotify parts, unsuffixed for the logic and its fakes).
- **Linux paths:**
  - drop-in `/run/systemd/resolved.conf.d/ghostline.conf`
  - `/etc/resolv.conf` and its temp file `/etc/resolv.conf.ghostline.tmp`
  - backup copy `<DataDir>/resolv.conf.orig`
  - marker line `# Generated by Ghostline`
  - secret key `<DataDir>/secret.key` (0600)
  - daemon lock `<run>/daemon.lock`
  - data dir mode 0700
- **Loopback servers:** `127.0.0.1`, plus `::1` when v6.
- **New codes (with vi/en strings):** `PORT53_NOT_OWNER` (error), `DNS_REAPPLIED` (log).
- **Commits:**
  - Style is `type(scope): sentence`, on branch `feat/linux-l3`.
  - **Never** add a `Co-Authored-By` trailer or a "Generated with" line.
- **Verify after every task:**
  - `go test ./...`
  - `GOOS=windows go vet ./...`
  - `go run ./tools/depcheck`
  - Run golangci-lint for both OSes before the last task.

**Rulings against the spec (Task 15 updates the spec):**
- **Snapshot types live in `model`:** `model.DNSSnapshot` and friends, aliased in `sysdns`, so `store` need not import `sysdns`.
- **`Backend` gains `StillOurs(s) Snapshot`.** Windows' watchdog restores only adapters still on loopback; Linux implements the same notion per backend.
- **`Reconcile` returns `[]sysdns.Change{Target string; Added bool}`, not `[]string`,** so the log code (`ADAPTER_ADDED` vs `DNS_REAPPLIED`) is chosen without branching on the backend name.
- **`Info` also carries `Adapters []sysdns.Adapter`,** so `Service.ListAdapters` and the Windows picker keep working unchanged.

## Review Focus

1. **A new adapter appears while connected on Windows** (USB tethering, a VPN NIC).
   - Expected: it is snapshotted first, then pointed at loopback, and `ADAPTER_ADDED` is logged, exactly as `OnNetworkChange` does today.
   - Test: Task 1, `TestAdapterBackend_ReconcileAddsNewAdapter`.
2. **After a crash, the user re-configured an adapter's DNS by hand before Ghostline's restore ran.**
   - Expected: that adapter keeps the user's settings.
   - Tests: Task 1, `TestAdapterBackend_StillOursKeepsUserChanges`; Task 3 watchdog test.
3. **NetworkManager's global DNS is edited (or NM restarted with another config) while connected.**
   - Expected: Ghostline applies it again, and Disconnect restores the value from before Connect, not the edited one.
   - Test: Task 7, `TestNM_ReconcileReappliesAndKeepsOriginal`.
4. **`/etc/resolv.conf` is a symlink** (to `/run/systemd/resolve/stub-resolv.conf`, `/run/NetworkManager/resolv.conf`, …).
   - Expected: restore recreates the same symlink, not a copy of its contents.
   - Test: Task 9, `TestResolvConf_RestoresSymlink`.
5. **A crash between "snapshot written" and "apply done"** (state `dns_set`, system untouched).
   - Expected: recovery restores nothing that is not Ghostline's: NM's global DNS, the resolved links and `resolv.conf` are left alone.
   - Tests: Task 7, `TestNM_StillOursOnlyWhenLoopback`; Task 8, `TestResolved_StillOursNeedsDropIn`; Task 9, `TestResolvConf_StillOursNeedsMarker`.

  type Selection struct{ Mode string; IDs []string }
  type Change struct{ Target string; Added bool }

      Backend     string    `json:"backend"`
      Chain       string    `json:"chain"`
      Interfaces  []string  `json:"interfaces"`
      AdapterPick bool      `json:"adapterPick"`
      Adapters    []Adapter `json:"adapters"`
  }
  type Backend interface {
      Name() string
      Snapshot(sel Selection) (Snapshot, error)
      Apply(s Snapshot, v6 bool) error
      Reconcile(s Snapshot, v6 bool) (Snapshot, []Change, error)
      StillOurs(s Snapshot) Snapshot
      Restore(s Snapshot) []RestoreError
      RestoreDefault() error
      Flush() error
      Watch(onChange func()) (stop func(), err error)
      Info() Info
  }
  // AdapterBackend changes adapters through api (Windows). watch reports adapter changes.
  func NewAdapterBackend(api API, watch func(onChange func()) (func(), error)) Backend
  type UnsupportedBackend struct{} // Snapshot/Apply/RestoreDefault → errors.ErrUnsupported; Restore → nil; StillOurs → empty; Flush → nil; Watch → no-op stop; Info{Backend:"unsupported"}

- `AdapterBackend` (`Name()=="windows"`, in the unsuffixed `adapters.go`):

  - `Apply`: `ApplyLoopback(s.Windows, v6)`.
  - `Reconcile`: today's `OnNetworkChange` loop. For each selected adapter whose GUID is not in `s.Windows`, snapshot it and append it to the returned snapshot, then apply it. Each one is reported as `Change{Target: alias, Added: true}`. An adapter whose apply fails is still kept in the snapshot, and the method returns an error naming it.
  - `StillOurs`: today's `watchdog.stillOurs` (via `LoopbackAdapters`).
  - `RestoreDefault`: today's corrupt-state path. `LoopbackAdapters`, then restore each to DHCP.
  - `Info`: `AdapterPick: true`, `Adapters` from `api.Adapters()`, `Chain: "Windows"`.
