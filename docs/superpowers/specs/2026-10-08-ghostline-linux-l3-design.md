# Ghostline — Linux L3 (DNS hệ thống + khôi phục): Thiết kế

- **Ngày:** 2026-10-08
- **Trạng thái:** Chờ duyệt spec
- **Phạm vi:** Sub-spec L3 của [Hỗ trợ Linux](2026-10-07-ghostline-linux-design.md): interface DNS trung lập cho mọi hệ điều hành, ba backend DNS trên Linux, theo dõi và áp lại cấu hình, khôi phục, cổng 53, ngủ/thức, `secrets` trên Linux. Sau L3, bấm Connect trên Linux bật được DNS mã hoá cho cả máy.
- **Dựa trên:** [spec tổng Linux](2026-10-07-ghostline-linux-design.md) (§6, §7, §13, §15, §20), [L2](2026-10-07-ghostline-linux-l2-design.md) (đã merge vào `feat/linux`). Spec này chỉ ghi phần chi tiết thêm hoặc khác spec tổng; mọi thứ không nhắc lại ở đây giữ nguyên.

---

## 1. Mục tiêu

- Bấm Connect trên Ubuntu 24.04, Fedora 41, Arch hoặc SteamOS đều chuyển DNS cả máy sang Ghostline, kiểm tra rò rỉ báo sạch. Disconnect trả DNS về đúng như trước.
- DNS luôn được trả lại: khi daemon crash, khi bị kill, khi mất điện.
- Interface DNS của orchestrator trung lập: không còn GUID hay adapter trong code dùng chung. macOS sau này chỉ cần thêm một backend.
- Windows không đổi hành vi.

### Tiêu chí thành công

1. **Trên máy có NetworkManager + systemd-resolved** (máy dev CachyOS, Fedora 41, Ubuntu 24.04 desktop): Connect → `resolvectl status` hiện `127.0.0.1` ở phần Global, `dig example.com` đi qua Ghostline, kiểm tra rò rỉ sạch. Disconnect → `GlobalDnsConfiguration` trở về giá trị cũ.
2. **Trên máy chỉ có systemd-resolved** (job CI Ubuntu 24.04): Connect → drop-in `/run/systemd/resolved.conf.d/ghostline.conf` xuất hiện và các link có `DefaultRoute` tắt. Disconnect → drop-in biến mất và `DefaultRoute` trở về như cũ.
3. **Trên máy chỉ có `/etc/resolv.conf`:** Connect → file trỏ về loopback. Có tiến trình khác ghi đè file → trong ≤ 3 giây Ghostline áp lại. Disconnect → file (hoặc symlink) trở về đúng như trước.
4. **`kill -9` daemon khi đang kết nối:** `ExecStopPost=--restore` trả DNS về trong ≤ 5 giây. **Rút điện:** daemon khởi động lại lúc boot và khôi phục trước mọi việc khác.
5. **Cổng 53 bị dnsmasq giữ:** UI hiện tên tiến trình và tên unit. "Dừng dịch vụ xung đột" chỉ dừng đúng unit đó; tên unit khác bị từ chối.
6. **Ngủ rồi thức** khi đang kết nối: engine được kiểm tra lại như `OnResume` trên Windows.
7. **Windows:** mọi test cũ pass. `state.json` v3 (kể cả bản dở dang sau crash) nạp vào thành v4 đúng. CI Windows xanh.

## 2. Phạm vi

### Có

| Nhóm | Nội dung |
|---|---|
| Interface trung lập | `sysdns.Backend`, `sysdns.Snapshot`, `sysdns.Selection`, `sysdns.Info`. Orchestrator, watchdog và `app.DNS` chỉ dùng chúng |
| Windows | Backend `windows` gói `Manager` hiện có. Logic "adapter mới xuất hiện" chuyển từ `app/health.go` vào `Reconcile` |
| Linux | Backend `networkmanager`, `resolved`, `resolvconf`, cùng `Detect()` |
| `state.json` v4 | Trường `dns` thay cho `snapshot`. Migration từ v3 |
| Theo dõi | `Backend.Watch`; `internal/netwatch` (netlink) trên Linux |
| Cổng 53 | `procs` Linux: `PortOwners` (`/proc`), `StopService` (systemd D-Bus). `StopConflictingService` chỉ dừng service đang giữ cổng 53 |
| Ngủ/thức | `platform.WatchResume` (logind `PrepareForSleep`) |
| `secrets` Linux | `secrets.NewFileKey` (AES-GCM, khoá root `0600`) |
| UI | `Service.DNSInfo()`; trang Cài đặt hiện ô chọn adapter (Windows) hoặc dòng backend chỉ đọc (Linux) |
| Mã mới | `PORT53_NOT_OWNER` (lỗi), `DNS_REAPPLIED` (log), có chuỗi trong `vi.json` và `en.json` |
| Từ L2 (Minor) | `data/` quyền `0700`; daemon `slog.SetDefault`; `daemon.lock` trước `core.New`; câu trả lời RPC quá lớn trả lỗi |

### Không có

- DPI, proxy hệ thống, kho chứng chỉ, firewall, SSID trên Linux → L4.
- Đóng gói, cài đặt, SteamOS → L5.
- Backend `openresolv`/`resolvconf(8)` riêng: máy dùng nó vẫn đi qua backend `resolvconf` (ghi trực tiếp file).

## 3. Các quyết định đã chốt

| Chủ đề | Quyết định |
|---|---|
| Hướng | Interface trung lập (spec tổng §6.1). Chọn vì kiến trúc và khả năng mở rộng, Windows được bảo vệ bằng test |
| Backend NM | `GlobalDnsConfiguration` qua D-Bus. Chỉ dùng khi `DnsManager.Mode` khác `none` |
| Backend resolved | Drop-in trong `/run` + `SetLinkDefaultRoute(false)`. Không dùng `RevertLink` (xoá cả cấu hình của networkd) |
| Backend resolvconf | Ghi file tạm rồi `rename`, có dòng đánh dấu `# Generated by Ghostline`; bản gốc chép vào `data/resolv.conf.orig`. Không dùng `chattr +i` |
| D-Bus | `github.com/godbus/dbus/v5` (đã có trong go.sum; thành phụ thuộc trực tiếp, không thêm module) |
| Netlink | `golang.org/x/sys/unix`, không thêm thư viện |
| `state.json` | v4. Bản Windows cũ (v0.5) đọc v4 sẽ không thấy snapshot (xem §10) |
| Theo dõi | Thuộc về backend (`Backend.Watch`). `platform.WatchNetwork` bỏ |
| Dừng service xung đột | Kiểm tra trong `app` (dùng chung): tên phải nằm trong `PortOwners(53)` hiện tại |

### Quyết định khi triển khai (L3)

- Kiểu dữ liệu snapshot (`DNSSnapshot`, `LinuxDNS`…) nằm trong `internal/model`, để `store` và `sysdns` cùng dùng mà không import lẫn nhau; `sysdns.Snapshot` là alias.
- `Backend.StillOurs(s)` trả phần snapshot mà Ghostline vẫn đang giữ; watchdog chỉ khôi phục phần đó (thay cho `watchdog.stillOurs` riêng của Windows).
- `Backend.Reconcile(s, sel)` chỉ ghi nhận, không áp dụng: trả `(next, toApply, changes)`. Orchestrator lưu `next` vào `state.json` trước rồi mới `Apply(toApply)`, giữ thứ tự write-ahead. `sel` là lựa chọn adapter auto/manual (Windows cần, Linux bỏ qua).
- `Change{Target, Added}` báo adapter mới (`ADAPTER_ADDED`) hoặc cấu hình bị ghi đè và đã áp lại (`DNS_REAPPLIED`).
- `Info.Adapters` thay cho `ListAdapters` riêng; `Info.AdapterPick` cho Settings biết có hiện bộ chọn adapter hay không.
- Daemon giữ `flock` trên `daemon.lock` trước mọi việc khác, nên chỉ một `ghostlined` chạy.

## 4. Interface

```go
package sysdns

// Backend changes the system's DNS through one mechanism of one OS.
type Backend interface {
    Name() string                                          // "windows", "networkmanager", "resolved", "resolvconf"
    Snapshot(sel Selection) (Snapshot, error)              // records what Apply will change
    Apply(s Snapshot, v6 bool) error                       // points it at 127.0.0.1 (and ::1)
    Reconcile(s Snapshot, v6 bool) (Snapshot, []string, error) // after a network change: the updated snapshot and what it touched
    Restore(s Snapshot) []RestoreError
    RestoreDefault() error                                 // "Restore DNS now" without a snapshot
    Flush() error
    Watch(onChange func()) (stop func(), err error)        // network or DNS configuration changed (debounced)
    Info() Info
}

type Selection struct {
    Mode string   // "auto" | "manual" (Windows adapters; ignored elsewhere)
    IDs  []string // manual choice
}

type Snapshot struct {
    Backend string                  `json:"backend"`
    Windows []model.AdapterSnapshot `json:"windows,omitempty"`
    Linux   *LinuxSnapshot          `json:"linux,omitempty"`
}

// Servers lists the DNS servers in use before Ghostline (the ISP lookup source).
func (s Snapshot) Servers() []string

type RestoreError struct {
    Target string // adapter alias, "NetworkManager", "/etc/resolv.conf", …
    Err    error
}

type Info struct {
    Backend      string   `json:"backend"`      // as Name()
    Chain        string   `json:"chain"`        // e.g. "NetworkManager → systemd-resolved"
    Interfaces   []string `json:"interfaces"`
    AdapterPick  bool     `json:"adapterPick"`  // the UI offers the adapter choice (Windows)
}
```

`LinuxSnapshot`:

```go
type LinuxSnapshot struct {
    NMGlobal      *NMGlobalDNS    `json:"nmGlobal,omitempty"`
    ResolvedLinks []ResolvedLink  `json:"resolvedLinks,omitempty"`
    DropIn        bool            `json:"dropIn,omitempty"`
    ResolvConf    *ResolvConfFile `json:"resolvConf,omitempty"`
    Servers       []string        `json:"servers,omitempty"`
}
```

`NMGlobalDNS`, `ResolvedLink`, `ResolvConfFile` mang đúng các giá trị của mục 5.

### 4.1 Orchestrator và watchdog

| Hiện nay | Sau L3 |
|---|---|
| `DNS.Select` + `DNS.Snapshot([]Adapter)` | `DNS.Snapshot(Selection)` |
| `DNS.ApplyLoopback([]AdapterSnapshot, v6)` | `DNS.Apply(Snapshot, v6)` |
| `DNS.Restore([]AdapterSnapshot)` | `DNS.Restore(Snapshot)` |
| `OnNetworkChange`: tự tìm adapter mới | `DNS.Reconcile` → ghi snapshot mới vào `state.json` trước → log `ADAPTER_ADDED` (Windows) hoặc `DNS_REAPPLIED` (Linux) cho mỗi mục trả về |
| `restoreNow` (shell/core): đặt các adapter loopback về DHCP | `DNS.RestoreDefault()` |
| `watchdog.Restorer` (`Restore`, `LoopbackAdapters`) | `Restore(Snapshot)`, `RestoreDefault()` |
| `Service.ListAdapters` | Giữ (Windows); thêm `Service.DNSInfo() sysdns.Info` |

- Thứ tự Connect, các bước rollback và mã lỗi giữ nguyên.
- Fake trong test của `app` giữ tên lời gọi (`dns.snapshot`, `dns.apply`, `dns.restore`, `dns.flush`) để các test thứ tự hiện có vẫn kiểm chứng đúng hành vi.

### 4.2 `state.json` v4

```jsonc
{ "version": 4, "phase": "dns_set", "dns": { "backend": "networkmanager", "linux": { "nmGlobal": {}, "servers": ["192.168.1.1"] } }, … }
```

- Nạp v3: `snapshot: [...]` → `dns: {backend: "windows", windows: [...]}`. Có test cho v3 sạch, v3 dở dang (`dns_set`) và v3 hỏng.
- Ghi luôn là v4.

## 5. Ba backend Linux

### 5.1 `networkmanager`

- **Khả dụng:** tên `org.freedesktop.NetworkManager` có chủ trên system bus, NM tự ghi `resolv.conf` (`DnsManager.Mode` khác `none` và `systemd-resolved`, `RcManager` khác `unmanaged`).
- **Không dùng khi `dns=systemd-resolved`:** lần chạy root trên NM 1.58 cho thấy NM giữ `GlobalDnsConfiguration` cho riêng nó (hiện trong `DnsManager.Configuration`) nhưng không đẩy sang resolved; không truy vấn nào tới `127.0.0.1`. Khi đó dùng backend `resolved` (§5.2).
- **Snapshot:** đọc `GlobalDnsConfiguration`. Server gốc lấy từ `DnsManager.Configuration[].nameservers`.
- **Apply:** đặt `GlobalDnsConfiguration = {"domains": {"*": {"servers": ["127.0.0.1"(, "::1")]}}}`, giữ `searches` cũ. Sau đó đọc lại `DnsManager.Configuration`; sai thì báo `SET_DNS_FAILED` (orchestrator rollback như hiện nay).
- **Reconcile:** giá trị hiện tại khác giá trị đã áp → áp lại, trả về `["NetworkManager"]`.
- **Restore:** đặt lại đúng giá trị cũ (rỗng nếu trước đó rỗng).
- **RestoreDefault:** chỉ xoá khi giá trị hiện tại là của Ghostline (chỉ chứa loopback).
- **Watch:** `PropertiesChanged` của NM và của `DnsManager`, cộng `netwatch`.
- **Lưu ý:** NM ghi giá trị này xuống đĩa, nên các tầng khôi phục (§7 spec tổng) bắt buộc chạy. Tiêu chí 4 kiểm tra việc này.

### 5.2 `resolved`

- **Khả dụng:** `org.freedesktop.resolve1` có chủ (và backend NM không khả dụng, kể cả khi NM chạy `dns=systemd-resolved`).
- **Snapshot:** các link có DNS, cùng cờ `DefaultRoute` của chúng. Server gốc lấy từ `DNS` của link.
- **Apply:**
  1. Ghi `/run/systemd/resolved.conf.d/ghostline.conf` (`[Resolve]`, `DNS=127.0.0.1 ::1`). Không có `Domains=~.`: server global đã nhận mọi truy vấn không khớp domain của link nào khi `DefaultRoute` của các link tắt, còn `~.` thì resolved (systemd 262) vẫn giữ trong Global sau khi xoá drop-in và reload.
  2. `ReloadUnit("systemd-resolved.service", "replace")` qua D-Bus của systemd.
  3. `SetLinkDefaultRoute(ifindex, false)` cho từng link trong snapshot.
- **Reconcile:** link nào có DNS mà `DefaultRoute` bật lại (do networkd đẩy) → tắt; link mới → thêm vào snapshot rồi tắt.
- **Restore:** xoá drop-in, reload, đặt lại `DefaultRoute` cũ cho từng link còn tồn tại.
- **RestoreDefault:** xoá drop-in của Ghostline nếu có, rồi reload.
- **Watch:** `PropertiesChanged` của `resolve1` + `netwatch`.

### 5.3 `resolvconf`

- **Khả dụng:** luôn (backend cuối).
- **Snapshot:** `Lstat("/etc/resolv.conf")`: đích symlink, hoặc nội dung và quyền. Server gốc là các dòng `nameserver`.
- **Apply:**
  1. Chép bản gốc vào `data/resolv.conf.orig`.
  2. Ghi `/etc/resolv.conf.ghostline.tmp` rồi `rename`, với nội dung `# Generated by Ghostline`, `nameserver 127.0.0.1`, (`nameserver ::1`), `options edns0 trust-ad`.
- **Reconcile:** file không còn dòng đánh dấu → coi nội dung mới là bản gốc mới (mạng mới), cập nhật snapshot, áp lại, trả về `["/etc/resolv.conf"]`.
- **Restore:** tạo lại symlink, hoặc ghi lại nội dung với quyền cũ (ghi file tạm rồi `rename`).
- **RestoreDefault:** file còn dòng đánh dấu và `data/resolv.conf.orig` tồn tại → trả lại bản đó; không có bản gốc → báo lỗi (không đoán).
- **Watch:** inotify trên `/etc` (lọc `resolv.conf`) + `netwatch`.
- Đường dẫn gốc và thư mục dữ liệu được tiêm vào để test trong thư mục tạm.

### 5.4 Chung

- `Flush`: `resolve1.FlushCaches` nếu có resolved; `nscd -i hosts` nếu có `nscd`.
- `Detect(conn) Backend`: NM → resolved → resolvconf. Backend ghi trong snapshot là backend dùng để khôi phục, kể cả khi máy đã đổi cơ chế.
- **D-Bus:** mỗi backend dùng một interface nhỏ (`nmAPI`, `resolvedAPI`, `systemdAPI`). Bản thật dùng godbus; test dùng fake.

## 6. `netwatch`

- `netwatch.Watch(onChange func()) (stop func(), err error)`: socket `NETLINK_ROUTE` với các nhóm `RTMGRP_LINK`, `RTMGRP_IPV4_IFADDR`, `RTMGRP_IPV6_IFADDR`, `RTMGRP_IPV4_ROUTE`, `RTMGRP_IPV6_ROUTE`.
- Debounce 2 giây, giống Windows.
- Gộp chung với tín hiệu riêng của backend trong `Backend.Watch`.

## 7. Cổng 53

- `procs.NewLinux().PortOwners(port)`:
  - Đọc `/proc/net/{udp,udp6,tcp,tcp6}` lấy các socket đang nghe cổng `port` (TCP ở trạng thái `0A`).
  - Từ inode tìm ra PID qua `/proc/*/fd`.
  - `Name` lấy từ `/proc/<pid>/comm`, `Service` là đuôi `.service` trong `/proc/<pid>/cgroup`.
- `StopService(name, wait)`: `StopUnit(name, "replace")` qua D-Bus, rồi chờ `ActiveState` thành `inactive` hoặc `failed` trong `wait`.
- `Service.StopConflictingService(name)`: nếu `name` không có trong `PortOwners(53)` hiện tại thì trả lỗi `PORT53_NOT_OWNER`, không dừng gì. Áp dụng cho mọi hệ điều hành.

## 8. Ngủ/thức, `secrets`, hardening

- **`platform.WatchResume`:** Linux nghe tín hiệu `PrepareForSleep` của `org.freedesktop.login1` (`false` = vừa thức), Windows là nil. `core.Start` đăng ký nó → `Orch.OnResume`.
- **`secrets.NewFileKey(path)`:** khoá 32 byte, tạo lần đầu với quyền `0600`. Mỗi blob gồm nonce 12 byte cộng ciphertext (AES-256-GCM). `UserSecrets` và `MachineSecrets` trên Linux dùng chung khoá này.
- **Thư mục:** `core.OpenLog` tạo `DataDir` với quyền `0700`. Nếu thư mục đã có với quyền rộng hơn thì chỉnh lại (trên Linux).
- **Daemon:**
  - `slog.SetDefault(log)`.
  - Lấy `flock` trên `<run>/daemon.lock` trước `core.New`. Không lấy được → báo "another ghostlined is running" rồi thoát, không làm gì khác.
- **RPC:** câu trả lời dài hơn `MaxLine` được thay bằng lỗi `rpc: reply too large`.

## 9. Kiểm thử

| Mức | Nội dung |
|---|---|
| Unit (CI cả hai OS) | Mỗi backend Linux với fake D-Bus và thư mục tạm: Snapshot → Apply → Reconcile → Restore cho ra trạng thái cũ; `RestoreDefault` không đụng cấu hình không phải của Ghostline. Backend Windows: các tình huống `OnNetworkChange` hiện có chuyển thành test `Reconcile`. Migration `state.json` v3 → v4. Orchestrator với fake `Backend`. `StopConflictingService` từ chối tên không giữ cổng. `secrets` file key: round-trip, khoá sai, blob hỏng. `procs` Linux: `PortOwners` thấy một listener do test mở |
| Integration (CI Linux, `sudo`, tag `integration`) | Backend `resolved` và `resolvconf` trên runner thật: Apply → kiểm tra → Restore → đúng như trước. `ghostlined --daemon` + `kill -9` → `--restore` trả DNS về |
| Thủ công (máy dev, NM + resolved) | Tiêu chí 1, 4 (kill -9), 5, 6 với `sudo ./bin/ghostlined --daemon` |
